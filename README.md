# EducationTishchenko
# Event Management API

REST API для управления мероприятиями с системой бронирования. Проект реализован на ASP.NET Core Web API с хранением данных в памяти.

## Технологии

- .NET 10
- ASP.NET Core Web API
- Swagger / Swashbuckle
- In-Memory хранилище (`List<Event>`, `List<Booking>`)
- xUnit + Moq (юнит-тесты)
- Потокобезопасность: `lock`, `SemaphoreSlim`

---

## Функциональность

| Метод | URL | Описание |
|-------|-----|----------|
| `GET` | `/api/events` | Получить список событий с фильтрацией и пагинацией |
| `GET` | `/api/events/{id}` | Получить событие по ID |
| `POST` | `/api/events` | Создать новое событие |
| `POST` | `/api/events/batch` | Создать несколько событий за один запрос |
| `PUT` | `/api/events/{id}` | Обновить событие целиком |
| `DELETE` | `/api/events/{id}` | Удалить событие |
| `POST` | `/api/events/{id}/book` | Создать бронирование на событие (202 Accepted / 409 Conflict) |
| `GET` | `/api/bookings/{id}` | Получить статус бронирования |

## 🧾 Модель Event

| Поле | Тип | Описание |
|------|-----|----------|
| `Id` | `Guid` | Уникальный идентификатор события |
| `Title` | `string` | Название (макс. 300 символов) |
| `Description` | `string?` | Описание (опционально) |
| `StartAt` | `DateTime` | Дата и время начала (UTC) |
| `EndAt` | `DateTime` | Дата и время окончания (UTC) |
| `CreatedAt` | `DateTime` | Дата создания |
| `TotalSeats` | `int` | **Общее количество мест (обязательное, > 0)** |
| `AvailableSeats` | `int` | **Текущее количество свободных мест (при создании = TotalSeats)** |

### Методы Event

| Метод | Описание |
|-------|----------|
| `TryReserveSeats(int count = 1)` | Возвращает `false`, если мест недостаточно. Иначе уменьшает `AvailableSeats` и возвращает `true`. |
| `ReleaseSeats(int count = 1)` | Освобождает места (вызывается при отклонении брони). |

## 🧾 Модель Booking

| Поле | Тип | Описание |
|------|-----|----------|
| `Id` | `Guid` | Уникальный идентификатор брони |
| `EventId` | `Guid` | Идентификатор события |
| `Status` | `BookingStatus` | Текущий статус брони |
| `CreatedAt` | `DateTime` | Дата создания |
| `ProcessedAt` | `DateTime?` | Дата обработки (заполняется при Confirm/Reject) |

### Статусы (`BookingStatus`)

| Статус | Описание |
|--------|----------|
| `Pending` | Бронь создана, ожидает обработки |
| `Confirmed` | Бронь подтверждена |
| `Rejected` | Бронь отклонена |

## 🔒 Синхронизация и потокобезопасность

В спринте 4 добавлена защита от **овербукинга** при конкурентных запросах.

| Примитив | Где используется | Зачем |
|----------|------------------|-------|
| **`lock`** | `BookingService.CreateBookingAsync` | Защищает атомарную пару «проверка доступных мест + создание брони». В один момент времени критическую секцию проходит только один поток. |
| **`SemaphoreSlim`** | `BookingBackgroundService.ProcessBookingAsync` | Асинхронный аналог `Mutex`. Используется вместо `lock`, потому что `lock` нельзя применять с `await` внутри блока. Защищает запись в хранилище. |
| **`Task.WhenAll`** | `BookingBackgroundService.ExecuteAsync` | Обеспечивает параллельную обработку всех Pending-броней. |

### Почему `lock`, а не `Interlocked`?

`Interlocked` защищает **только одну переменную**. Критическая секция в `CreateBookingAsync` включает:
1. Получение события из хранилища.
2. Проверку и резервирование мест (`TryReserveSeats`).
3. Создание и сохранение брони.

Все эти операции должны быть атомарными **вместе**, поэтому используется `lock`.

## ⚠️ Овербукинг и 409 Conflict

Эндпоинт `POST /api/events/{id}/book` может вернуть:

| Код | Описание |
|-----|----------|
| `202 Accepted` | Бронь создана, `Location: /api/bookings/{bookingId}` |
| `404 Not Found` | Событие не найдено |
| **`409 Conflict`** | **Нет свободных мест на событии** |
